## Definition contract

<ParamField path="profile.clientAlias" type="string" required>
  The approved client alias used in navigation, labels, and records. Demo value: **{profile.clientAlias}**.
</ParamField>

<ParamField path="profile.site.name" type="string" required>
  The physical or logical switch location. Demo value: **{profile.site.name}**.
</ParamField>

<ParamField path="profile.switch.systemName" type="string" required>
  The switch system name from the approved naming standard. Demo value: <code>{profile.switch.systemName}</code>.
</ParamField>

<ParamField path="profile.switch.management.address" type="IPv4 address" required>
  The unused management address assigned in the network records. Demo value: <code>{profile.switch.management.address}</code>.
</ParamField>

<ParamField path="profile.services.syslogCollector" type="IPv4 address">
  The collector for direct standalone XDR syslog. Omit this value from the direct-switch procedure for a NAC-managed design.
</ParamField>

<ParamField path="profile.switch.monitoring.mode" type="string" required>
  Selects the direct switch-to-collector path. This value must be false when the NAC platform owns event forwarding.
</ParamField>

<Warning>
  Do not put passwords in the profile. Point the technician to the approved password source.
</Warning>

## How authors use the profile

<CodeGroup>

```jsx Define once
export const client = {
  services: {
    ntpServer: "192.0.2.20",
    syslogCollector: "192.0.2.30"
  },
  switches: {
    northAccess1: {
      systemName: "5320-48P-8XE-NORTH-01",
      management: { address: "192.0.2.10", prefixLength: "24" }
    }
  }
};
```

```mdx Refer everywhere
import { profile } from "/snippets/switch-profile.mdx";

Connect to `{profile.switch.systemName}` at
`{profile.switch.management.address}`.
```

</CodeGroup>

<Tip>
  For production, generate one profile from controlled client records or deliver values after authentication. Do not copy live client data into a public repository.
</Tip>
