The source template marks optional material in orange and tells the author to remove sections. This page keeps every supported path visible and names the condition that controls it.

## Monitoring path

<Tabs>
  <Tab title="NAC-managed" icon="shield-halved">
    Use this path when XIQ-SE or another approved NAC platform manages the switch and forwards the required monitoring events.

    <Info>
      Do not add direct standalone-switch syslog commands only because they exist in the template. Follow the separate NAC switch-onboarding standard and send the required alerts from the NAC platform to the defined collector.
    </Info>

    Record the switch in the NAC platform, apply the approved authorization and monitoring policy, and validate the event path from NAC to the collector.
  </Tab>
  <Tab title="Standalone XDR" icon="satellite-dish">
    Use this path only when the client has standalone switch XDR and no NAC-managed event path.

    ```bash standalone-xdr.cli {1-2}
    configure syslog add 192.0.2.30 vr VR-Default local0
    enable syslog
    save config
    ```

    <Check>
      Generate or observe a supported switch event, then confirm that the defined collector receives it with the correct hostname and source address.
    </Check>
  </Tab>
</Tabs>

## Backup path

<Tabs>
  <Tab title="Kiwi CatTools" icon="clock-rotate-left">
    Use the approved Kiwi CatTools standard to add the device, schedule backups, store credentials securely, and confirm the first successful configuration capture.

    <Tip>
      A scheduled backup must still be tested. Confirm that the job captures a current configuration after you save a switch change.
    </Tip>
  </Tab>
  <Tab title="Manual backup" icon="floppy-disk">
    Use manual backup only when the client has no approved automated method. Use the approved transfer host and protected storage location.

    ```bash manual-backup.cli
    upload config 192.0.2.40 5320-48P-8XE-NORTH-01.xsf vr VR-Default
    ```

    Verify that the file exists, has a current timestamp, and can be read. Do not install an unapproved transfer service on a shared server.
  </Tab>
</Tabs>

## Voice path

<AccordionGroup>
  <Accordion title="Voice VLAN is required" icon="phone">
    Follow the approved VoIP network standard. Confirm the voice VLAN ID, tagging method, handset behavior, and switch-port design before you add the VLAN.
  </Accordion>
  <Accordion title="Voice VLAN is not used" icon="phone-slash">
    Do not create a dormant voice VLAN. Keep the unused template section out of the client implementation scope.
  </Accordion>
</AccordionGroup>

## MFA access path

<Tabs>
  <Tab title="User access" icon="user-check">
    Connect by SSH with the assigned administrative username. Enter the password and the current MFA code in the format required by the RADIUS service. A successful RADIUS login returns the approved user prompt.
  </Tab>
  <Tab title="Break-glass admin" icon="triangle-exclamation">
    <Warning>
      Use local administrative access only under the approved break-glass process. Do not disable a firewall rule for convenience or leave an MFA control disabled after the session.
    </Warning>

    If the documented recovery design requires a temporary RADIUS block, obtain approval, record the change, enable the exact pre-existing block rule, wait for the defined timeout, complete the local session, and then disable the block rule. Test MFA again before you close the work.
  </Tab>
</Tabs>
