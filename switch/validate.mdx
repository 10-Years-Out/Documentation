title: "Validate and hand off"
description: "Prove that the switch configuration works, is saved, is monitored, is backed up, and is recorded in client documentation."
icon: "clipboard-check"
---

Validation is part of the implementation. Do not close the work because the commands ran without an error.

## Acceptance checks

<Steps titleSize="h2">
  <Step title="Confirm identity and firmware">
    ```bash identity-check.cli
    show switch
    show version
    show configuration
    ```

    Confirm the model, serial number, system name, installed image, and expected configuration state.
  </Step>
  <Step title="Confirm management and time">
    ```bash management-check.cli
    show vlan default
    show iproute
    show management
    show ntp
    ```

    Confirm the management address, default route, secure SSH access, NTP server, timezone, and synchronized time.
  </Step>
  <Step title="Confirm VLANs and ports">
    ```bash network-check.cli
    show vlan
    show ports information detail
    show ports description
    ```

    Compare every VLAN tag, access port, tagged uplink, and description with the approved port map.
  </Step>
  <Step title="Confirm the selected monitoring path">
    For standalone XDR, confirm the syslog target and collector receipt. For a NAC-managed switch, confirm onboarding, policy, and event forwarding in the NAC platform.
  </Step>
  <Step title="Confirm backup and saved state">
    Run `save config`. Trigger or observe a new backup. Compare its timestamp with the final configuration change.
  </Step>
  <Step title="Confirm physical work">
    Check the system-name label, management-address label, port-group labels, rack position, cable labels, and uplink connections.
  </Step>
</Steps>

<Check>
  The implementation passes when the live device state, saved configuration, backup, monitoring path, and client records all describe the same switch.
</Check>

## Record evidence

| Evidence | Minimum record |
| --- | --- |
| Device identity | Model, serial number, MAC address, system name, location |
| Network state | Management address, route, VLAN list, port map, uplinks |
| Security | Secure SSH state, MFA path, failsafe access decision |
| Monitoring | NAC object or syslog collector, test event, receipt time |
| Backup | Method, job or file name, completion time, storage location |
| Documentation | Server Overview, IP list, LAN-WAN diagram, rack diagram, asset record |

## Update related documents

- Technical Overview or Server Overview.
- IP address list and network scheme information.
- LAN-WAN diagram.
- Server rack or location diagram.
- End-of-life asset management record.

<AccordionGroup>
  <Accordion title="The switch works, but the backup failed" icon="floppy-disk-circle-xmark">
    Keep the implementation open. Confirm credentials, transfer reachability, device prompt handling, and storage permissions. Do not treat a local `save config` as an external backup.
  </Accordion>
  <Accordion title="The collector has no switch events" icon="satellite-dish">
    Recheck which monitoring path applies. Confirm the collector address, route, source identity, NAC policy when present, and a known event that should produce a message.
  </Accordion>
  <Accordion title="The live state differs from the records" icon="files">
    Stop and resolve the difference. Determine whether the implementation or the record is wrong, obtain approval for the correction, and update every affected source.
  </Accordion>
</AccordionGroup>
