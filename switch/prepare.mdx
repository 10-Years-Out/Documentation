Do not connect the switch until the client records identify one consistent address plan and monitoring design. A configuration builder cannot resolve conflicting source data.

## Prerequisites

Before you begin, you must have:

- The approved Server Overview, IP address list, LAN-WAN diagram, and rack or location record.
- The switch serial number, MAC address, part number, and support entitlement.
- An unused management address and the correct prefix and gateway.
- The intended VLAN names, IDs, access ports, tagged uplinks, and purpose of each VLAN.
- The applicable monitoring and backup choices.
- An approved administrative account source. Do not put its password in the documentation profile.

<Warning>
  Stop if an expected address is already in use or two records disagree. Resolve the conflict before you configure the device.
</Warning>

## Choose the deployment path

<Tabs>
  <Tab title="New switch" icon="box-open">
    Record the factory state, connect by serial console, complete the initial security prompts, set management access, and then configure services and VLANs.
  </Tab>
  <Tab title="Replacement switch" icon="arrow-right-arrow-left">
    Capture the current switch configuration and port map first. Preserve the working VLAN and uplink design unless the approved implementation plan changes it.
  </Tab>

## Stage the work

<Steps>
  <Step title="Register the support asset">
    Use the client support account to register the serial number and confirm support coverage. Use the shared account pattern defined for the client. Do not store a support password in this site.
  </Step>
  <Step title="Prepare console access">
    Connect a workstation to the serial console. Confirm the assigned COM port and use these settings:

    ```text Console settings
    Bits per second: 115200
    Data bits:       8
    Parity:          None
    Stop bits:       1
    Flow control:    None
    ```
  </Step>
  <Step title="Confirm the firmware path">
    Record the installed ExtremeXOS version and release train. Review the current vendor recommendation and release notes before you select an image.
  </Step>
  <Step title="Confirm the physical plan">
    Mark the intended access ports, uplinks, redundant links, and any shared ports. Keep one port map that the configuration and physical labels both use.
  </Step>
</Steps>

<Accordion title="Why the profile must stay separate from the procedure" icon="circle-info">
  A reusable procedure should explain what to do. The profile supplies where and with which values. This separation lets one reviewed procedure support many client copies without copying every instruction into each document.
</Accordion>
