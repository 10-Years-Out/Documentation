The prototype uses Mintlify as more than a styled Markdown reader. It separates content, deployment data, interaction, and publishing features so each part can change without forcing a rewrite of the others.

## Capability map

| Capability | Where to see it | What it replaces |
| --- | --- | --- |
| Reusable client profile | [Demo Bank overview](/client/overview) | Repeated client values and copy errors |
| Custom React component | [Configuration builder](/switch/configure) | Manual command substitution |
| Conditional paths | [Optional paths](/switch/conditional-paths) | Orange notes that tell an author to remove sections |
| Task-based navigation | Switch implementation sidebar | One long procedure with mixed concerns |
| Steps, tabs, accordions, and callouts | Throughout the workflow | Dense nested bullets and inline warnings |
| Mermaid diagrams | [Overview](/switch/overview) | Separate process diagrams that drift from the text |
| Framed source images | [Overview](/switch/overview) | Uncaptioned images inside a page |
| Structured updates | [Revisions](/reference/revisions) | A revision table on a disposable last page |
| Print-ready audit record | [Switch configuration record](/deliverables/switch-configuration-record) | A separate hand-built auditor packet |
| Contextual AI actions | Page action menu | Copying content by hand into AI tools and editors |

## Three kinds of dynamic content

<AccordionGroup>
  <Accordion title="Shared build-time definitions" icon="database">
    The client overview exports one JavaScript object from a normal MDX page. Any standard can import a stable device role and show the same system name, address, gateway, services, VLAN plan, and feature choices.

    Change the profile once, then every page that consumes it builds with the new values.
  </Accordion>
  <Accordion title="Live reader input" icon="sliders">
    The configuration builder is a custom React component. It keeps values in browser state and regenerates the command set after each change. The page remains documentation, but it also becomes a small technician tool.
  </Accordion>
  <Accordion title="Authenticated personalization" icon="user-shield">
    A production site can receive user or organization data through Mintlify authentication. MDX can display fields from the `user` object and render role- or client-specific branches.

    This local demo does not enable authentication. The pattern is useful when a portal must show approved values only to the correct client or team.
  </Accordion>
</AccordionGroup>

## One site, different readers

<Tabs>
  <Tab title="Technician" icon="screwdriver-wrench">
    The technician gets prerequisites, a live configuration builder, copyable commands, explicit environment choices, and a final validation record.
  </Tab>
  <Tab title="Author" icon="pen-to-square">
    The author changes the client profile once, reviews it through the overview, and keeps optional instructions in named branches. The content model makes unresolved decisions visible during review.
  </Tab>
  <Tab title="Reviewer" icon="clipboard-check">
    The reviewer can follow the same task order as the technician, inspect the source values, and read a structured revision history with filter tags.
  </Tab>
</Tabs>

## Authoring pattern

<CodeGroup>

```jsx Shared profile
export const client = {
  switches: {
    northAccess1: {
      systemName: "5320-48P-8XE-NORTH-01",
      management: { address: "192.0.2.10" },
      monitoring: { mode: "standalone-xdr" }
    }
  }
};
```

```mdx Use the profile
import { profile } from "/snippets/switch-profile.mdx";

Connect to `{profile.switch.systemName}` at
`{profile.switch.management.address}`.
```

```mdx Personalize after sign-in
Welcome, {user?.firstName ?? "technician"}.

{user?.standaloneXdr
  ? <>Follow the direct syslog path.</>
  : <>Follow the NAC onboarding path.</>}
```

</CodeGroup>

<Note>
  Local search and the hosted AI assistant require a Mintlify account or deployed project. The repository already enables contextual actions for copying, viewing, AI tools, MCP, Cursor, and VS Code.
</Note>

<Info>
  Mintlify can export a complete public documentation site as a PDF on Enterprise plans. PDF export is not available for authenticated sites, so this demo also includes a page-specific print layout for browser printing or saving as PDF.
</Info>
